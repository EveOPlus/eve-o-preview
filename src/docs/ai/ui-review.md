# UI review and modernization acceptance map

This is a source review of the Windows UI on 2026-09-07, prepared for the Light, Dark and Legacy redesign. It inventories the starting behavior rather than claiming that every behavior has been exercised on a live EVE session. The implementation notes for the new shell should be read alongside this preservation map. Future DPS and ESI entries describe extension requirements, not implemented integrations.

The implementation uses the [portable Avalonia workspace and Windows adapter](application-and-configuration.md). Light and Dark share task-based navigation. Legacy recreates the original compact window and control positions. The [recorded validation](build-and-test.md#ui-modernization-validation-recorded-2026-09-07) distinguishes the initial rendering checks from the follow-up usability corrections. The acceptance map below remains broader than those checks; it does not imply that live EVE, Linux or every accessibility scenario was tested.

## Scope and evidence

Reviewed the production [MainForm](../../Eve-O-Preview/View/Implementation/MainForm.cs), [designer](../../Eve-O-Preview/View/Implementation/MainForm.Designer.cs), [view contract](../../Eve-O-Preview/View/Interface/IMainFormView.cs), [presenter](../../Eve-O-Preview/Presenters/Implementation/MainFormPresenter.cs), [configuration](../../Eve-O-Preview/Configuration/Implementation/ThumbnailConfiguration.cs), [client picker](../../Eve-O-Preview/View/Implementation/ClientNameInputBox.cs), [preview view](../../Eve-O-Preview/View/Implementation/ThumbnailView.cs), [preview designer](../../Eve-O-Preview/View/Implementation/ThumbnailView.Designer.cs), [overlay](../../Eve-O-Preview/View/Implementation/ThumbnailOverlay.cs), and the application, window, build and backlog guides. The separate AboutBox is excluded from production compilation; the live About page belongs to MainForm.

The starting settings window has a 460 by 417 logical-pixel client area, a left tab rail approximately 120 pixels wide, nine pages, and a mixture of fixed positioning and split containers. It has no settings search or overview, no theme selection, and no always-visible active-profile indicator. Some controls use system colors while preview menus use hard-coded dark/gold colors. `MinimizeBox` is false even though tray lifecycle behavior exists.

## Review findings

### Follow-up: fidelity and useful density

User review rejected the initial oversized settings pages and approximate Legacy styling. The earlier screenshots established that controls rendered; they did not establish a usable editing workflow or visual equivalence to the original.

- **Title accuracy:** the first sample multiplied font size by 1.333, centered the title regardless of configured offsets, and used a different outline/fill drawing order. Windows now exposes `IWorkspacePreviewRenderer`, rendering the actual production `OutlinedLabel` into an image without changing saved settings. The title text, family, size, style, colors, outline and offsets follow the live overlay. Active highlight insets use the same aspect-preserving geometry as the native preview. The sample is preview content against a neutral background, not a live game capture or an OS window-frame simulation.
- **Editing workflow:** layout, title/highlight and behavior settings are separate compact sections. Keep the title preview visible while editing; expose installed font choices, style controls, color selection and exact numeric values. Draft edits update the sample before Apply, and invalid edits remain visible without being persisted. Actual pixel size is the default; Fit is an explicit option. The compact layout must leave useful room for the editor, not merely keep a large preview visible.
- **Density:** remove decorative space from daily tasks. Group shortcuts belong beside character order; bound long member/profile lists instead of letting them push every later control further down a page. Global shortcuts have their own clearly named section.
- **Legacy reference:** capture the real `MainForm` on an isolated Windows desktop and compare against it. At 96 DPI its client area is 460 × 417, its left tab rail is 120 pixels with 35-pixel rows, and its font is Segoe UI 9 pt. Recreate original captions, ordering, group boxes, list placement and system-gray controls. Native font/color dialogs retain the old interaction. Additional appearance options must not displace the familiar nine tabs.

Regression coverage must compare rendered title pixels to the production overlay, inspect original and replacement Legacy pages, and exercise editing with the preview still in view at compact size. Counting screenshots or checking only control existence is insufficient for these acceptance criteria.

## Preservation matrix: visible settings and actions

Each row is a capability requirement for all themes. Modern information architecture may combine categories. The user's follow-up requires Legacy to look nearly identical to the original WinForms interface: preserve the compact dimensions, left-rail order and actual control positions, while allowing small accessibility and additional-feature accommodations.

| Starting page / surface | Controls and actions to preserve | Behavior and boundaries |
| --- | --- | --- |
| General: visibility | Previews always on top; hide active client's preview; minimize inactive EVE clients; hide previews when EVE is not active | These are distinct policies. Temporary global hiding and permanent per-title hiding remain separate. Keep nonactivating preview raising and priority-client behavior. |
| General: layouts | Track client locations; unique thumbnail layout for each EVE client | Preserve game-window layouts versus preview layouts as separate concepts and retain dictionary-clearing semantics when disabled. |
| General: application / CPU | Minimize to System Tray; Dynamic CPU Affinity Strategy | Close/minimize/tray restoration and explicit Exit retain the presenter lifecycle. CPU changes retain native service application and reset behavior. |
| Thumbnail | Width; height; opacity | Size is bounded by profile minimum/maximum, normally 192 by 108 through 960 by 540. Opacity is 20 to 100 percent. Preview-resize feedback updates settings under suppression. |
| Zoom | Zoom on hover; factor; nine anchors | Factor 2 through 10. Anchor order is NW, N, NE, W, C, E, SW, S, SE. Dependent controls communicate whether hover zoom is enabled. |
| Overlay: frame | Show overlay; show frames; highlight active client; highlight color | Theme changes must not replace the user's configured game-preview colors. Per-client highlight overrides remain preserved. |
| Overlay: title | Font family, size and style; foreground color; outline color and width; left and top offsets; sample | Font styles include bold, italic, underline and strikeout. Outline width supports fractions and is restricted to 0 through 20. Signed offsets are intentional. The sample must distinguish app theme styling from preview styling. |
| Active Clients / All Clients | Running named-client list; per-client force-hide state; Hide All / Show All; Minimize All | Preserve full-title identity. Hide All is transient and must have visible state even after changing pages. Distinguish hidden-by-policy from user-disabled where the host can provide this information. |
| Active Clients: shortcuts | Hide All shortcut; Minimize All shortcut | Hotkey capture, duplicate validation, timeout, retaining current binding and clearing remain available through explicit affordances. |
| Cycle Groups: group | Select; create; remove; rename/description | Empty groups and deleting the final group are supported. Creating/removing a group must not discard unrelated groups or bindings. Group changes persist and refresh registration. |
| Cycle Groups: members | Add a known or manually typed client; reject duplicates; remove; ordered list; move up | Offline full-title entries remain valid. Cancel/empty selection makes no edit. Preserve selected identity during reorder. Existing persisted order keys need not be contiguous. |
| Cycle Groups: shortcuts | Two visible forward and two visible backward shortcut fields | The persisted lists can contain more than two entries; editing displayed entries must not truncate additional ones. A single-character group implements a direct character shortcut. |
| FPS / Audio: FPS | Enable DirectX FPS limits; active, inactive and predicted client targets | Separate enable and target-change routes apply settings to known clients. The old UI max is 500 while current model validation permits up to 1000; use deliberate validated bounds rather than inheriting a display accident. Zero is valid and represents disabled limiting for a role. |
| FPS / Audio: presets | Mute Jump Gate Tunnel; Mute Asteroid Belt Warp In | Keep the established player-facing label **Mute Asteroid Belt Warp In** in all themes. It maps to persisted `MuteLocationBanner`; preserve that field name and actual preset behavior. Do not use the internal location-banner name as the UI label. |
| FPS / Audio: custom | Comma-separated event IDs; validation; clear | Accept decimal unsigned 32-bit values, ignore empty entries, deduplicate in input order. Any invalid token preserves the previous saved list. Empty input clears only custom IDs. Old commits occur on Enter, leaving the field and close; new commit behavior must stay explicit. |
| Profiles | Current name; list/select; clone current; delete current; rename | Default appears first and cannot be renamed/deleted. Cloning saves current state. Rename validates filesystem-safe names and existing-name collisions; old view also limits to 50 characters. Deletion identifies the actual current profile and requires deliberate confirmation in the UI. |
| About | Product name; version; description; community/documentation link; maintainer credit; liability/license information | Preserve relevant notices and real destinations. Remove stale placeholder copy, including resource-era experimental language if it no longer describes the feature. Open external links through the host's controlled external-link action. |
| Client picker dialog | Known names; editable offline name; Select; double-click selection; cancellation | Keep full `EVE - Name` values unchanged for persistence. Empty/cancelled input must not add a blank member. Modern shell may implement this inline if keyboard and cancellation behavior remains clear. |
| Color/font dialogs | Current value; edit; accept; cancel | Cancellation retains the previous value. Portable equivalents may replace native dialogs while preserving font/color capabilities. |
| Tray | Application title; Restore; Exit; double-click restore | Restore must show the existing settings instance, not start another application loop. Explicit Exit bypasses close-to-tray and completes existing cleanup. |
| Preview menu | Minimize client; Move; Resize; Minimize All | Keep these actions reachable and preserve native focus/geometry callbacks. Move/Resize use global mouse tracking and end on mouse-up. |
| Preview gestures | Left-click activate; Ctrl-left-click deactivate/minimize; right-click menu; held right-click move; Shift-resize keeps ratio; hover zoom | Held right-click begins moving after 350 ms. Ctrl-Shift-left-click currently does nothing. Do not assign new gestures that conflict with these without an explicit behavior decision. |

## Preserve advanced customization beyond the visible form

The old settings form is not the entire configuration surface. [IThumbnailConfiguration](../../Eve-O-Preview/Configuration/Interface/IThumbnailConfiguration.cs) and the serialized implementation additionally expose these settings, some only through profile JSON. A new shell that reads a smaller DTO must update selected fields on the existing configuration or round-trip the remaining model without deleting it.

| Existing advanced field | Meaning / compatibility requirement |
| --- | --- |
| `ThumbnailRefreshPeriod` | Discovery/property-maintenance interval; currently clamped to 300 through 1000 ms. DWM rendering remains live independently. |
| `HideThumbnailsDelay` | Nonnegative number of maintenance cycles before focus-loss hiding, not milliseconds. |
| `CompatibilityMode` | Historical JSON name for `EnableCompatibilityMode`; selects captured/static versus DWM views and requires the established renderer-change lifecycle. |
| `EnableThumbnailSnap` | Existing neighbor snapping; does not imply snap-to-grid or automatic fleet layout. |
| `ThumbnailMinimumSize`, `ThumbnailMaximumSize` | Profile-specific geometry bounds; preserve legitimate small custom values and validate dimension ordering. |
| `ActiveClientHighlightThickness` | Border width, restricted to 1 through 6. |
| `LoginThumbnailLocation` | Default x/y for login windows whose title is `EVE`. |
| `PerClientActiveClientHighlightColor` | Full-title-to-color overrides; do not discard during theme or global color changes. |
| `PriorityClients` | Full-title exceptions to minimizing inactive clients; private JSON property remains persisted. |
| `PerClientLayout`, `FlatLayout`, `ClientLayout`, `DisableThumbnail` | Persisted layout/visibility maps; native handles are runtime identities and must not replace full-title keys in old profiles. |
| General and group hotkey lists | Preserve string contracts and extra entries; parsed WinForms `Keys` are runtime-only and should not leak into a portable frontend protocol. |
| `ConfigVersion`, historical property aliases | Existing migrations must continue to work. Adding UI theme metadata must not reinterpret old settings or remove unknown preserved fields. |

The workspace now exposes these user-configurable options: **Previews & layout → Advanced** handles refresh/hide timing, snapping, compatibility, resize bounds and login position; **Clients → Character colors & minimization** handles per-character colors and priority exceptions, including offline names. Legacy has compact links to the same editors. Existing preview/title, layout, visibility and hotkey controls cover the remaining options. Parsed keys, migrations and layout maps remain internal storage details. Trace edits through persistence and `ThumbnailRuntimeSettingsUpdated`, particularly timer changes, grouped size bounds, renderer replacement and active highlights; adding a widget alone is insufficient.

## Theme and portability contract

Light and Dark use the same task-oriented navigation, settings scope, command semantics and validation, and receive all new features. Legacy is locked to its existing feature set for legacy use only. Do not add new features, pages or controls to it; preserve its familiar layout while continuing bug fixes, compatibility work and updates to existing features through the shared implementation. Users are expected to migrate to a modern theme. Show a brief, nonmodal notice when selecting Legacy that newer features may be unavailable. Switching themes must preserve the selected profile, edited values, client/cycle selection and temporary Hide All state.

The theme is an application-wide preference: switching gameplay profiles keeps Light, Dark or Legacy selected. Store it in the generic `EVE-O Preview.settings.json` global configuration file, following the existing portable-folder/AppData location pattern. Preserve unrelated global fields so later application preferences can share the file; avoid separate files for each theme or preference category.

Each gameplay profile separately stores an accent color to give that profile a recognizable visual identity. The active profile name and accent should be visible together; color alone must not identify a profile. Changing the accent applies immediately, survives save/reload, follows cloning, and changes on profile switch without changing the global theme. Empty/old/invalid values use the selected theme's accent. Limit customization to the profile identity cue, with useful palette suggestions and validated hex input; keep readable theme colors for body text and actions. This first customization feature is not an unrestricted CSS/font/layout editor. Profile accents must not overwrite independently configured preview highlight or title colors.

Use stable page identifiers and a small theme/token model rather than hard-coding colors throughout each page. Include hover/pressed/disabled/focus/error states, selection visibility, readable links and long-label wrapping. Keyboard navigation and accessible control names are functional requirements. Respect reduced motion where animation exists. Validate Light and Dark contrast from rendered output; do not claim compliance solely because tokens exist.

Keep portable shell state, navigation and commands separate from Windows `HWND`, WinForms controls, GDI font/color objects, global input hooks, DWM, tray services and Robin. The current application uses Windows APIs throughout discovery, focus, rendering, hotkeys, CPU affinity and injection, so a portable UI alone does not make the app run on Linux. A future Linux host will need capability-specific implementations and clear unavailable states. The first Windows release should preserve the existing nonactivating DWM and native audio/FPS paths, as documented in [Windows and thumbnails](windows-and-thumbnails.md) and [Robin](robin.md).

## Future DPS and ESI extension requirements

Implement these future capabilities in modern themes only. Their tabs and placeholder links are hidden in all themes. Reserved IDs and module registration remain in the code; follow [the module handoff](../../Eve-O-Preview.UI/AGENTS.md#future-workspace-modules). Dormant Legacy placeholder code does not authorize adding its eventual features to Legacy.

| Extension | UI model to leave room for | Implementation boundary for a later feature |
| --- | --- | --- |
| Character hub | Running/offline identity, display name, connection state, per-character actions and configurable detail pages | Keep runtime window identity, persisted title identity and future EVE character ID distinct. Character rename/logout must not orphan associations. |
| ESI connections | Per-character Connect/Reconnect/Disconnect, granted data access, expired/revoked/error/loading state and last sync | Define required scopes from actual features. Auth/token storage and refresh belong in host services, not theme assets, page state or ordinary profile JSON. Never fabricate connected accounts or show a working login control before implementation. |
| DPS overview | Select characters/data source, overview name, displayed measures, grouping, time window, reset behavior and overlay/display placement | Define what DPS means and available event sources before choosing a UI. Live logs, cached history and ESI data must not be treated as interchangeable; do not promise real-time damage from an unimplemented API. |
| Dashboard widgets | Discoverable add/configure/remove flow; empty/loading/stale/error states; per-profile layouts | Use extension metadata and stable routes so future modules do not require a new top-level tab for every option. Keep high-frequency telemetry away from discovery, DWM refresh and synchronous UI save paths. |
| Capability-aware settings | Explain availability per operating system and active backend | Frontend should consume capability/state descriptions. Windows-only controls may remain visible with a reason when unavailable; avoid silently changing what an identical setting means on another OS. |

These are design seams for the user's future ideas, not authorization to perform ESI authentication, collect account tokens, or implement speculative game-log metrics now. Existing backlog items [FEAT-014 through FEAT-017](feature-backlog.md) provide related scope context.

## Validation acceptance

The character-order follow-up adds scrollbar clearance, drag handles with edge scrolling and keyboard alternatives, an editor that fills the existing window without maximizing it, and Skip/Resume controls. Skip state is shared across all groups of a profile for the current session. The thumbnail context menu provides the same toggle and the title shows a configurable marker, including when names are hidden. Legacy preserves its compact list and original editing controls while adding selected-character Skip/Resume and an expanded editor. See [the implementation contract](application-and-configuration.md#character-order-and-temporary-skips).

1. Compare every matrix row with all three themes. Test first launch, an existing customized profile, empty clients/groups and long client/profile names. Verify no undocumented advanced settings are lost after edit/save/reload.
2. Exercise theme switching in place, restart persistence, invalid theme fallback, page navigation/search and keyboard-only editing. Verify per-profile accents survive clone/reload, change with the selected profile, retain the global theme, and do not alter configured preview colors. Inspect narrow/wide window sizes, enlarged text and all page content, including dialogs and validation messages.
3. Verify callback routing and reload suppression for ordinary settings, geometry, fonts, cycles, FPS/audio and profiles. Check hotkey collisions/cancel/timeout; invalid custom audio and profile names must leave saved values intact.
4. Validate tray restore, close-to-tray and explicit shutdown. Confirm current native preview gestures, nonactivation, stable DWM registrations and overlays remain covered by focused tests.
5. Keep browser/shell screenshots, compiled host checks, isolated Windows tests and live EVE observations distinct. A UI smoke run with sample clients is not evidence of real injection, audio muting, mixed-DPI behavior, screen-reader quality or Linux support.

For this review document, validate relative links and `git diff --check`; no application launch is necessary. Implementation validation belongs in the modern shell guide and [build-and-test](build-and-test.md), recording what actually ran and any remaining manual checks.
